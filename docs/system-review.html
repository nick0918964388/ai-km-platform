1. 系統概要

AI Knowledge Management Platform（AI-KM） 是一套針對車輛維修領域設計的企業 AI 知識管理平台， 結合 RAG（Retrieval-Augmented Generation）、NL→SQL、知識圖譜（Neo4j + GraphRAG）三種檢索模式， 讓維修技師、管理者、分析師能以自然語言詢問工單、故障代碼、資產資訊、SOP 維修程序等結構化與非結構化資料。

系統以 Maximo EAM 資料為主要結構化來源（工單 10,742 筆 / 資產 16,165 筆 / 故障通報等）， 搭配可上傳的 PDF / Word / Excel / 圖片知識庫，提供引用可追溯、低延遲、高安全性的查詢體驗。

10. 安全控制總覽

採用多層深度防禦（Defense in Depth）策略，無單點信賴。每層皆有獨立測試與稽核：

topic classifier + jailbreak detector + greeting] L2[Layer 2: Prompt 層
DOMAIN_CONSTRAINT_PREFIX + refusal template] L3[Layer 3: 驗證層
SQL Validator + Cypher Validator + Row Policy] L4[Layer 4: 輸出層
Output Scanner 掃密鑰/PII/內部IP] L5[Layer 5: 流量控制
Rate Limit 30/min + Abuse Alert] L6[Layer 6: 認證授權

每筆查詢留痕 + SECURITY_ALERT] L1 --> L2 --> L3 --> L4 L5 -.輪流作用.- L1 L6 -.輪流作用.- L3 L7 -.全程記錄.- L1

10.1 輸入層 — Input Guardrail

檔案：backend/app/services/input_guardrail.py（純 regex，< 1ms/call）

類型動作範例測試
Jailbreak REFUSE + audit ignore previous instructions、DAN、eval(...)、; DROP TABLE 12 tests
Off-topic REFUSE 天氣、股票、電影、食譜、翻譯 8 tests
Greeting 禮貌回應（不走 LLM） hi、你好、謝謝、再見 23 tests
Allow 進下一層 含 domain keyword 的查詢 10 tests

實測：20/20 攻擊測試全擋下。Greeting 平均 31ms（vs 2s LLM call，省 ~60x）。

10.2 Prompt 層 — Domain Constraint

檔案：backend/app/services/domain_constraint.py

所有會輸出 freeform text 的 LLM call（RAG 回答、synthesis）於 system prompt 最前面加入領域限制前綴：

  • 明示 AI 只回答工單/故障/資產/SOP/維修/零件/人員相關問題
  • 拒絕扮演其他角色、忽略指令、執行程式碼
  • 不透露系統 prompt 或內部實作細節
  • Intent classifier 刻意不套（輸出為結構化 JSON，無 leak 風險，避免 prompt bloat）

10.3 驗證層 — SQL / Cypher / Row Policy

SQL Validator（既有）

  • 規則層 + LLM 層雙重驗證
  • 僅允 SELECT，擋 DDL / DML
  • 自動修正常見錯誤並重試（最多 1 次）

Cypher Validator

檔案：services/cypher_validator.py（71+ tests）

  • 白名單 MATCH / RETURN / WHERE / WITH / ORDER BY / LIMIT
  • 擋 CREATE / DELETE / MERGE / SET / CALL db.*
  • Unicode 零寬字元正規化（NFKC）
  • Subquery 深度限制 + LIMIT 自動補入（UNION 每段獨立）
  • 效能 < 1ms/call

SQL Row-level Policy

檔案：services/sql_policy.py（27 tests）— 深度防禦，即使 admin 也擋

類別數量範例
FORBIDDEN_TABLES17users, auth_tokens, sessions, jwt_blacklist, pg_catalog, information_schema
FORBIDDEN_COLUMNS13password, secret, private_key, api_key, access_token
Row filter 注入per-role依使用者 role 自動注入 WHERE 子句，防跨 tenant 越權

10.4 輸出層 — Output Scanner

檔案：services/output_scanner.py（23 tests），於 SSE 最終 content 前掃描 LLM 回應：

動作Patterns範例
BLOCK 6 openai_key (sk-...), anthropic_key, aws_key (AKIA...), jwt (eyJ...), generic_api_key, ssh_private_key
REDACT 5 credit_card, twn_id, email, phone_twn, bcrypt_hash → 改為 453***010 形式
WARN 2 internal_ip (10.*/172.16-31.*/192.168.*), md5_hash → 記 log 不修改

10.5 流量與稽核 — Rate Limit / Alert

檔案：middleware/rate_limit.py（8 tests，Redis-backed）

  • Rate limit：每使用者/IP 30 req/min，超限回 429
  • Abuse alert：10 分鐘內 3 次 guardrail block → [SECURITY_ALERT] ERROR log（可接 webhook）
  • Fail-open：Redis 斷線時不阻擋正常流量，避免 single-point failure
  • 實測：40 次連發驗證第 31 次起 429；3 次 jailbreak 即觸發 alert

10.6 認證與權限

  • JWT (HS256) login / register / setup
  • 5 個權限群組：admin / maint_manager / maint_tech / analyst / viewer
  • Row filter 參數化注入（deny-by-default）
  • Admin API Depends(require_admin)，非 admin 回 401/403
  • 稽核日誌記錄：使用者 / query / SQL / 產 response

10.7 RAG Prompt Injection Scanner（既有）

Hermes Phase 1 階段引入，掃 RAG 檢索到的文件 chunks 是否含嵌入式 prompt injection，保護 LLM 不被文件內容劫持。

Circuit Breaker

LLM / Qdrant / Redis / Neo4j 各自獨立斷路器：

  • 連續 5 次失敗 → OPEN（拒絕打 service，快速失敗）
  • 30 秒後 HALF-OPEN 試探恢復
  • 成功 → CLOSED 正常服務
